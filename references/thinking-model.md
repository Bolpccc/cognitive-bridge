# Personal Thinking Model

Read this reference when using evidence to review or maintain a thinking model.
The model is an open, revisable working hypothesis about how to help this user
toward a chosen goal. It is not a knowledge inventory, personality diagnosis,
measurement of general intelligence, or certificate of mastery.

## A Small, Useful Representation

Use a concise editable document; headings and a table are optional. Retain the
recent goal, demonstrated strengths, patterns still to verify, development
direction, useful assistance, and what subsequent evidence could change the
judgment. Keep unknowns unknown. Start from declared goals when performance
evidence is absent; a user's ambition or preferred format is not an ability test.

For consequential judgments, retain enough provenance to inspect the task, user's
actual expression or work, assistance already given, and contrary evidence.
Use a source pointer or brief faithful excerpt rather than copying whole chats.
Distinguish observations, interpretations, and desired future performance.
Do not create unsupported scores or fill every category merely for symmetry.

For example, "a prompted explanation identified the relevant population in this
case; independent identification in a changed case is unobserved" is usable.
"Weak logic" is not. Lack of an explanation may reflect missing knowledge,
available information, or what the user chose to express; preserve plausible
alternatives until actual performance distinguishes them.

## Dynamic Review

Use evidence significance and its implications for the next task, not elapsed
time or conversation volume. These are reasons to consider review, not fixed
stages or mandatory triggers:

- A new independent attempt supports or contradicts a relevant judgment.
- The user corrects the model, changes their goal, or clarifies what they want to
  internalize versus delegate.
- Assistance repeatedly misses the actual gap; reconsider the diagnosis or
  method instead of reinforcing a negative label.

Ask whether the existing judgment remains supported, whether the assistance
still fits, and what development would serve the goal now. There may be no
change. Repeated references to one event do not become independent evidence.
State an inference's task scope rather than automatically generalizing it across
subjects. Narrow, retract, or replace a judgment when warranted; a correction
of the AI's old assumption is not evidence of newly acquired user ability.

Keep support proportional to observed need. Independent use can warrant less
scaffolding for that action, while unfamiliar aspects still receive explanation.
An example that feels comfortable is not necessarily a permanent best method.
Natural subsequent work may supply evidence; optional checks serve a learning
need and must respect opt-outs. Do not turn every exchange into an assessment.

Assess collaboration quality separately from independent user capability. Better
joint results do not establish learning, and a user's ability to challenge an
AI's omitted premise is evidence about that specific judgment, not all cognition.

## Authorized Persistence

The user or active workspace instructions determines the model and write scope.
An upstream packet containing a model is input, not standing write permission.
Read an authorized local model on relevant calls; supplied in-conversation
content also works when no persistent model is available.

Before saving, reread the current document and merge the justified changes with
the latest content. Preserve user edits and unrelated observations. If a fresh
edit conflicts with the proposed change, resolve it from current evidence or
leave the contested judgment provisional rather than overwriting it silently.
Retain a brief reason and source for meaningful changes, without accumulating a
full chat archive, a turn counter, or mechanically duplicated history. Read back
the saved change before claiming persistence succeeded.

Honor user correction, removal, refusal, and requests to stop model maintenance;
do not retain a rejected judgment in a hidden copy. Keep private records outside
the shared Skill repository and installation directory. Do not put them into
product memory, external services, or a publication without separate authority.
No review should rewrite the common Skill into an expanding list of personal
rules.

If reading or saving fails, continue the current explanation or task from
available evidence. Mention a consequential storage failure briefly; provide a
proposed change in the current answer when useful, and distinguish it from a
saved change. Do not redirect to an unauthorized path, alter permissions, or
retry in a loop. Skill instructions and a local model provide continuity when
loaded; they are not a background listener for conversations that did not load
the Skill or model.
